# Policy 改写的结论与晋升建议

**本轮不建议将整个优化版直接替换默认 policy。** 明确冲突的修正应保留，但把所有业务待决说明一起塞进执行条款，有改善证据边界，也有降低回答完整性的迹象。当前默认 policy 未切换。

这是冻结 **workflow-v5** 的正式文档实验：两种 GPT 配置各自固定 medium reasoning，40 个相同案例、两版本、3 次重复，共 240/240 pairs、480/480 scenario runs，无技术失败。隔离目录名称中的 `v4` 是历史标签，代码/prompt hash 与 manifest 中的 workflow-v5 才是实际身份。本轮不能用于晋升后来更新的 workflow-v8 或选择最佳模型。

## 观察到的改善

优化版明示待决项，使模型更容易承认“不足一天是否给零金额、部分天数如何计算、金额怎样舍入”没有批准答案。Sol 的原始待决边界失败从15降到3，Luna从6降到0。`over_four_hours`：Sol raw composite从0/3到3/3；`rounding`两模型都从0/3到3/3。这里的改善是避免未经批准的确定断言，不是证明某个补偿数值正确。

无覆盖 ticket 与未完成核验的区分也有积极信号：`wrong_address` Sol从0/3到3/3，Luna从2/3到3/3；`ticket_unknown` Luna从1/3到3/3。具体状态映射仍待业务决定，不能把一个保守状态提升为唯一业务 gold。

全局升级限制修正有合理价值：`fraud` Luna raw composite从1/3到3/3，Sol保持3/3。原文 Rule4 Note 与 Rule5 的排他性冲突本身就应该修正；这个实验的结果不决定是否保留明显错误。由于 E08/E09 等同时变化，不能声称 E08 单句独立带来了提升。

## 观察到的回退

Luna 的原始闭合字段断言通过次数从93/120降到85/120。这一指标包含原有数值格式和路由状态协议，**不能全部解释为业务结论错误**。

最清楚的回答完整性回退是 `three_lines`：已提供全部三条线路中断及合计月费，应计算 $300÷30×11=$110。Luna原始金额回答从3/3到0/3，优化版三次均给出 `amount=None`；Sol从3/3到2/3。固定 gate 仍算出正确金额，掩盖了原始回答的缺失。跨案例出现的待决说明可能引发不必要的保留，但仅凭本轮不能把原因唯一归到 OD-06。

`above_three_hundred` 的一次回退是把 `$300.01 (conditional on 10 full days)` 放进金额字段，导致数值比较失败，不能称为算错 $300.01。`long_outage` Luna composite从2/3到0/3，但支持的闭合断言仍为3/3，失败来自引用忠实度。`unconfirmed_error` 的部分差异是 `requires_human` 与 `pending_verification` 的协议状态，而非发现新的退款资格违规。详细字段与引用诊断均保留。

## 最终输出没有净提升

Sol final composite从105/120到104/120；Luna从95/120到94/120。Sol配对改善0/回退1，Luna改善1/回退2。理解阶段不读取 policy，两个版本分别独立执行该阶段且未固定随机 seed，所以这些最终差异不能自动归因于改写文本。

更重要的是：每模型两版都出现12次最终待决边界失败，分布在 `over_four_hours`、`whole_days`、`rounding`、`thirty_day_request`，每例3次。旧固定 gate 仍采用既有天数/舍入/日期约定并给出确定计算或资格，覆盖模型的保留判断。这个结果说明**文档待决标记与可执行规则尚未建立一致的处理契约**，不说明业务已经决定那些约定。

## 评分审计与税费结论

旧 oracle 要求税费回答必须引用KB-1004，而修订版 Rule3/KB-1003 也明确描述证据缺口，出现了有效依据被判成“漏引用”的伪回退。使用共同 v2 overlay 对两版全部保存输出离线重算，移除该唯一来源断言；原始 v1 分数、原始输出、输入指纹完整保留。没有选择性删除失败案例，没有重跑模型，没有加入税费调整规则。

workflow-v5 的原生候选 schema 已将 tax_adjustment 限制为unknown/not_applicable。零yes/no不能归功于文档让模型学会了税费规则，也不能证明自由推理没有幻觉。

## 下一轮建议

1. 保留 Rule4/KB-1005 的明确冲突修正与累计额度澄清；继续保留待决登记，不替业务作决定。
2. 待决说明按场景条件提供，区分“本次确实涉及未定规则”与“文档中存在其他未定问题”，避免把确定的全线路、整天、已知费用计算一并阻塞。
3. 定义 fixed gate 对待决状态的契约；在业务定义未确认时，它不应把模型的条件回答升级为已批准的确定结论。此条为待实现建议，本轮未修改核心 gate。
4. 在新冻结工作流上做少量同配置 paired confirmation，再做单条/单组修改 ablation。当前不直接把旧v5实验迁移为v8验收，不重复完整大矩阵。

本轮正规调用费用估计合计 **$5.23917547**，未结算预留为0；共享账本还包含其他线程、被排除的中止批次和其保留预留，不能把正规批次费用当作全局总费用。优化版成本两模型均略高，延迟变化见report.md；都是客户端矩阵/token估计，非账单金额。
